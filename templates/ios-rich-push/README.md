# iOS Rich Push (images, carousels, rating widgets)

This is a bigger step than basic push — two real Xcode targets are involved. No plugin tooling (this
plugin's `plugin.xml`, Capacitor's CLI, or React Native autolinking) can create an Xcode target
automatically; that part is always manual, on every platform. This folder exists so the code side isn't
hand-typed from scratch once those targets exist.

Applies equally to Cordova and Capacitor apps — both consume this same plugin, and the steps below are
identical except for which `.xcworkspace` you open.

- Cordova: `platforms/ios/<App>.xcworkspace`
- Capacitor: `ios/App/App.xcworkspace`

## 1. Create the two extension targets (Xcode, manual)

In Xcode: **File → New → Target**

- **Notification Service Extension**, name it `NotificationService`
- **Notification Content Extension**, name it `NotificationContent`

## 2. Replace the generated source

- Copy [`NotificationService.swift`](./NotificationService.swift) into the `NotificationService` target,
  replacing the file Xcode generated.
- Copy [`NotificationViewController.swift`](./NotificationViewController.swift) into the `NotificationContent`
  target, replacing the file Xcode generated. Leave `MainInterface.storyboard` as Xcode generated it.

## 3. Add the two pods, scoped to the new targets only

```ruby
target 'NotificationService' do
  use_frameworks!
  pod 'WEServiceExtension'
end

target 'NotificationContent' do
  use_frameworks!
  pod 'WEContentExtension'
end
```

- **Cordova:** `platforms/ios/Podfile` is regenerated by Cordova — see the warning below before you add this.
- **Capacitor:** add it to `ios/App/Podfile`, which is NOT regenerated by `cap sync`, so it survives normally.

Then run `pod install` from the directory containing that Podfile.

## 4. Add the rich-push categories to the Content Extension's Info.plist

Xcode already generated an `NSExtension` dict in `NotificationContent/Info.plist` — merge these keys into its
existing `NSExtensionAttributes` dict (don't replace the whole file):

```xml
<key>UNNotificationExtensionCategory</key>
<array>
    <string>WEG_CAROUSEL_V1</string>
    <string>WEG_RATING_V1</string>
    <string>WEG_RICH_V1</string>
    <string>WEG_RICH_V2</string>
    <string>WEG_RICH_V3</string>
    <string>WEG_RICH_V4</string>
    <string>WEG_RICH_V5</string>
    <string>WEG_RICH_V6</string>
    <string>WEG_RICH_V7</string>
    <string>WEG_RICH_V8</string>
</array>
```

## 5. App Groups capability (all 3 targets: main app, NotificationService, NotificationContent)

Add the **same** App Group ID to all three targets' Signing & Capabilities tab:

```
group.<your-bundle-id>.WEGNotificationGroup
```

Mismatched or missing-on-one-target App Group IDs are the single most common cause of rich push silently
falling back to plain text — this is tracked as KI-15 ("WebEngage App Group not configured") if you hit it.

## 6. Build, then test from the WebEngage dashboard

A text-only push working is not evidence rich push works — send an actual image/carousel push from the
dashboard and confirm the image/carousel renders.

---

> 🚧 **Cordova-specific warning:** `platforms/ios` is regenerated by `cordova platform remove ios && cordova
> platform add ios`, and some `cordova prepare` flows touch the Podfile. Manually-added targets, their
> `Info.plist` edits, and the Podfile entries above do not survive that regeneration — if you do it, redo this
> whole setup. This risk does not apply the same way to Capacitor, where `ios/App` persists across
> `npx cap sync` (only the separate, gitignored `ios/capacitor-cordova-ios-plugins/` folder is regenerated).
